# UAV 仿真平台：已实现内容全景介绍

> 面向第一次接触本项目的读者。读完本页，你可以快速理解：我们做了什么、系统怎么跑、当前已经支持哪些实验与分析能力。

---

## 1. 这个项目要解决什么问题

本项目是一个“**协议仿真 + 日志分析 + 可视化管理**”的一体化平台，核心目标是验证和对比 UAV 与 ZSP 之间的 D2Z 认证流程在不同网络与攻击条件下的表现。

当前重点协议为：

- `PMAP`：经典模式，UAV 发完 `M3/M4` 后本地立即轮换 `PID/CRP`。
- `PMAP_ACK`：增强模式，UAV 必须收到 ZSP 的 `D2Z_ACK` 后才提交轮换；若 ACK 超时，UAV 保持旧身份并重试，体现会话冗余与恢复机制。

## 2. 当前系统由哪些部分组成

### 2.1 协议仿真层（NS-3 + 实体逻辑）

- `Entity/UAV/PMAPUAV.py`：UAV 侧协议状态机（D2Z + D2D）。
- `Entity/ZSP/PMAPZSP.py`：ZSP 侧认证、库更新、ACK 控制与去同步攻击注入点。
- `Protocol/PMAP/`：消息类型、明文结构体、线级包编解码。
- `simulator_builder.py` / `Simulator/simulator_builder.py`：从任务配置构造拓扑、注入实体并启动仿真。

### 2.2 统一日志层

- `Common/logging_framework.py` 定义统一日志模型（JSONL），包括：
  - 认证阶段事件（INITIATED / SUCCESS / FAILED）
  - 消息收发与错误事件
  - 会话建立、PID 轮换、数据库操作等
- 每个实体独立日志文件，便于跨 UAV / ZSP 追踪。

### 2.3 后端 API 层（FastAPI）

- 入口：`Backend/app.py`
- 路由：
  - `Backend/api/routes/simulation.py`：创建/运行/查询任务
  - `Backend/api/routes/events.py`：事件分页与过滤
  - `Backend/api/routes/metrics.py`：性能指标聚合
  - `Backend/api/routes/analysis.py`：会话、时间线、导出
- 核心服务：
  - `Backend/services/log_service.py`：任务日志目录解析、缓存与分析器调用
  - `Backend/core/log_parser.py`：将 JSONL 事件解析为 D2Z 事件流
  - `Backend/analysis/protocol_analyzer.py`：会话识别、成功率/耗时/字节/错误统计

### 2.4 前端层（React）

- `Frontend/src/components/SimulationManager.jsx`：
  - 场景化创建任务
  - 协议选择（PMAP / PMAP_ACK）
  - 任务列表、运行、详情
  - **任务 ID 一键复制**
- `Frontend/src/components/AnalysisDashboard.jsx`：
  - 输入 `task_id` 后按任务目录分析
  - 指标卡片（成功率、消息效率、耗时、错误）
  - 会话表格与时间线查看

## 3. 已完成的核心能力（按业务闭环）

## 3.1 任务管理闭环

已实现“创建任务 -> 落盘配置 -> 后台运行 -> 状态查询”的完整流程：

- 任务 ID 采用 `sim_时间戳_uuid`，避免并发碰撞。
- 每个任务在 `~/UAV_Simulation/tasks/<task_id>/` 下有独立目录与 `config.json`。
- 运行时自动创建 `logs/` 子目录承载该任务的实体日志。

## 3.2 协议模式闭环

支持两种 D2Z 行为并可在前端切换：

- `PMAP`
- `PMAP_ACK`

`PMAP_ACK` 已完整支持：

- 新消息类型：`D2Z_ACK`（`Protocol/PMAP/MsgType.py`）
- ACK 明文结构：`old_pid | new_pid | challenge | response`
- UAV 仅在 ACK 校验通过后提交本地轮换
- ACK 超时自动重试，生成新的 `auth_session_id`

## 3.3 去同步攻击与恢复实验闭环

通过 `attack_model` + `desync_template` 实现协议无关注入：

- `uplink_rotation_drop`：丢弃上行 `M3/M4`
- `downlink_d2z_ack_drop`：抑制下行 `D2Z_ACK`

并已实现关键策略：

- 默认 `desync_attack_first_auth_only: true`
- 含义：每 UAV 仅第一次认证尝试触发去同步，后续恢复为正常路径，便于观察“超时 -> 重试 -> 恢复成功”。

## 3.4 日志到分析闭环

分析链路已打通：

1. 实体输出协议无关 JSONL 日志
2. 解析器聚合 UAV/ZSP 双边事件
3. 通过 `auth_session_id` 与 `(uav_id, zsp_id)` 关联会话
4. 分析器输出：
   - 成功/失败会话数
   - 成功率
   - 会话时延统计（平均/最小/最大）
   - 通信开销（消息数、字节、每成功会话开销）
   - 错误分布（M1/M2/M3M4 相关）

## 4. 前端目前有哪些可直接使用的场景

在仿真管理页已内置多种可直接运行场景（示例）：

- 基线 D2Z（双 UAV 双 ZSP）
- 单 UAV 多 ZSP 覆盖
- 短时压力回归
- 去同步：上行丢 M3/M4
- PMAP_ACK 基线
- PMAP_ACK 去同步（首次抑制 ACK，后续恢复）

这意味着新用户无需手写配置即可立刻复现实验。

### 阶段0建议固定的基线场景

为了在继续做动态性增强、多协议扩展前先稳住平台基线，当前建议优先固定以下 3 个场景作为阶段0回归入口：

- `baseline_d2z`
- `pmap_ack_baseline`
- `pmap_ack_attack_drop_ack`

这 3 个场景分别覆盖：

- 经典 PMAP 正常认证
- `PMAP_ACK` 正常 ACK 提交
- `PMAP_ACK` 首次去同步后的超时与恢复

## 5. 最近阶段已解决的关键问题（稳定性修复）

以下问题已经在代码中落地修复：

- **ACK 结构与解析一致性**：ACK 载荷明确含旧/新 PID 与 CRP，避免单靠包头 PID 绑定。
- **广播场景 ACK 处理鲁棒性**：UAV 在 foreign PID 过滤前先处理 ACK，减少误丢包。
- **去同步仅首次触发**：避免每轮认证都被攻击，确保恢复机制可观测。
- **ACK 处理异常链修复**：
  - 处理超长缓冲时按 ACK 单帧线长截取，避免粘包导致长度异常。
  - `bytes_to_pid` 同时兼容 `str` / `bytes`，修复 `'str' object has no attribute 'hex'`。
  - 解密返回 `bytes`，减少可变缓冲副作用。
- **任务使用体验增强**：任务列表新增“复制任务 ID”按钮，便于快速定位分析数据。

## 6. 数据流怎么走（一张脑图式理解）

1. 前端提交场景 -> 后端 `simulation/create`
2. 后端写入任务配置 -> `simulation/run/<task_id>`
3. NS-3 启动实体，UAV/ZSP 交互并写 JSONL
4. 前端分析页输入 `task_id`
5. 后端按 `tasks/<task_id>/logs` 解析
6. 输出 metrics/sessions/timeline/events
7. 前端展示指标、会话列表、时间线

对“功能已完成”可以用下面标准判断：

## 9. 当前边界与后续可扩展方向

### 已实现边界

- 重点覆盖 D2Z 链路与关键 D2D 分支。
- 分析模型围绕 D2Z 认证会话进行聚合。
- 阶段1最小切口已接入两类动态骨架：
  - UAV 可通过 `mobility.type = "trace"` + `trace_file` 从外部 JSON 轨迹文件加载航迹。
  - UAV 可通过 `auth_trigger` 配置时间触发与边缘 RSSI 触发认证。
- 前端已补入两类阶段1预置实验入口：
  - `dynamic_edge_recovery`：面向主实验 A 的动态边缘恢复场景。
  - `swarm_burst_auth`：支持 `10 / 30 / 50 / 100` UAV 的并发蜂群认证场景。
- 阶段1剩余能力已补齐为完整动态增强集：
  - 上层运动调度模式：`trace` / `patrol` / `formation` / `transit`
  - 认证触发模式：连接建立、时间窗口、边缘 RSSI、切换窗口
  - 链路状态绑定：距离阈值、边缘区域、预设失联窗口
  - 分析可见性：会话级 `trigger_reason` 与任务级 `trigger_breakdown`
  - 阶段1.5 文献对齐：主实验 A 拆分为 `mobility-induced` 与 `adversarial` 两个口径；主实验 B 拆分为 `network_congestion` 与 `protocol_compute_sensitivity` 两个子实验
  - 机制级指标：`Success vs Distance`、`Recovery Completion Ratio`、`Re-authentication Cost`

### 可扩展方向

- 多协议统一比较视图（同一任务多协议并行统计）
- 更强的异常归因（按 `protocol_step` 自动归类根因）
- 场景批处理与回归基线管理
- 结果导出模板（论文图表/实验报告）
